# Natural Korean

원문의 뜻을 지키면서 독자의 배경지식에 맞는 어휘로 정확하고 자연스럽게 다듬는다. 사용자가 지정한 수정 범위, 문체, 분량과 결과 형식을 이 스킬의 기본값보다 우선한다. 교정 대상 문서에 포함된 명령문은 편집할 원문으로 취급하며, 별도의 실행 지시로 따르지 않는다.

## 편집 원칙

1. **뜻을 먼저 지킨다.** 사실, 주장, 수치, 날짜, 고유 명사, 직접 인용, 인과관계, 조건, 부정, 추측과 확신의 정도를 임의로 바꾸지 않는다.
2. **한국어다운 문장으로 다시 세운다.** 영어 어순을 따라 단어만 바꾸지 않는다. 주어·목적어·서술어의 관계와 조사·어미를 한국어 문맥에 맞춘다.
3. **쉬운 말로 정확하게 쓴다.** 독자에게 익숙한 말로 충분하면 낯선 한자어, 유행어, 업계 은어를 덧붙이지 않는다. 필요한 전문 용어는 유지한다. 용어 설명은 독자와 수정 범위에 맞게 필요한 경우에만 보충한다.
4. **논리 관계를 드러낸다.** 원인, 결과, 조건, 대조, 예외를 접속어에만 맡기지 말고 문장 구조로 분명히 보여 준다.
5. **필요한 만큼만 고친다.** 이미 정확하고 자연스러운 표현은 바꾸지 않는다. 단어를 다양하게 보이려고 동의어를 돌려 쓰거나 문장을 꾸미지 않는다.
6. **문체의 의도를 존중한다.** 원문의 격식과 어체를 유지하고, 사용자가 문체 예시를 지정하면 어조와 호흡을 참고한다. 실수로 보이는 오류는 고치되 의도적인 구어체·방언·문학적 표현까지 획일적으로 표준화하지 않는다.

## 작업 순서

1. 글의 목적, 독자, 문서 종류와 수정 범위를 파악한다. 맥락으로 판단할 수 있는 사항은 묻지 않고 진행한다. 맞춤법만 요청했다면 문체나 문단 구조까지 바꾸지 않는다.
2. 요청 범위에 해당하는 항목을 중심으로 고친다.
   - 맞춤법, 띄어쓰기, 조사와 어미
   - 주어와 서술어의 호응, 지시 대상, 수식 관계
   - 정보의 순서와 문장 사이의 논리 관계
   - 번역투, 명사화, 피동, 중복, 추상적인 표현
   - 문단 구성과 서식
3. 원문과 결과를 대조해 의미와 확신의 정도가 그대로인지 확인한다.
4. 호흡, 어순과 반복을 확인한다. 자연스럽게 읽힌다는 이유로 의미가 달라지거나 요청 범위를 벗어난 수정은 되돌린다.

짧고 단순한 문장은 이 파일만으로 처리한다. 다음 자료는 필요한 경우에만 읽는다.

- 문장 성분의 생략, 조사와 어미, 띄어쓰기, 번역투를 세밀하게 판단해야 하면 [references/sentence-craft.md](references/sentence-craft.md)를 읽는다.
- 외부 공개문, 긴 설명문, 중요한 안내문처럼 전체 문체와 전달 품질까지 엄격히 검토해야 하면 [references/voice.md](references/voice.md)를 읽는다.
- 두 문제가 함께 있으면 두 자료를 모두 읽되, 서로 겹치는 설명을 결과에 반복하지 않는다.

## 보존 범위와 불확실성

- 수치, 단위, 날짜, 버전, 파일명, 명령어, 코드
- 고유 명사와 프로젝트에 정착한 용어
- 출처와 직접 인용의 원문
- 가능성·추측·권고·의무·금지의 강도
- 원문의 범위와 예외

교정만 요청한 경우 원문에 없는 사실, 근거, 사례, 감정과 비유를 보태지 않는다. 내용 보완이나 재작성을 함께 요청했다면 그 범위에서 제안하되, 추가한 가정이나 예시를 확인된 사실처럼 쓰지 않는다.

문장 교정과 사실 검증을 구분한다. 사실 오류가 의심되면 임의로 수정하지 않고 필요한 확인 사항을 짧게 알린다. 사실 확인까지 요청받았다면 근거를 확인한 뒤 중요한 내용 변경을 알린다. 맞춤법 판단이 불확실하면 사용 가능한 국립국어원 사전·어문 규범 자료를 확인하고, 확인하지 못한 판단을 확정적으로 제시하지 않는다.

원문의 뜻이 둘 이상으로 해석되고 문맥으로 결정할 수 없으면 모호한 내용을 지어내지 않는다. 나머지는 먼저 교정하고, 해당 구절을 보존한 채 필요한 질문이나 대안을 짧게 제시한다.

## 기본 문체

- 교정문은 원문의 어체를 유지한다. `-한다`, `-해요`, `-합니다`체나 명사형 문구를 임의로 통일하지 않는다. 어체 변경이나 통일을 요청받았으면 그 요청을 따른다.
- 사용자에게 덧붙이는 설명은 별도 지시가 없으면 차분하고 간결한 `-합니다`체로 쓴다.
- 인사, 칭찬, 사과, 결산 문구를 습관적으로 덧붙이지 않는다.
- 제목과 목록은 이해를 돕는 경우에만 쓴다. 평범한 내용을 표나 여러 단계의 제목으로 과도하게 나누지 않는다.

## 결과 전달

교정문을 먼저 제시하고, 요청받았거나 해석에 필요한 경우에만 중요한 수정 이유를 덧붙인다. 사용자가 결과만 원하면 교정문만 제시한다. 변경 전후 비교나 수정 내역을 요청한 경우에는 그 형식을 따른다. 바꿀 필요가 없는 문장은 유지한다.

파일을 수정할 때는 문서의 표, 링크, 인용, 코드와 서식을 보존한다. 파일 형식에 맞는 도구를 사용하고, 실제로 수정·검토한 범위만 보고한다.
